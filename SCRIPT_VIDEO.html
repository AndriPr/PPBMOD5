Tugas Pengganti Modul 5 PPB (Bore & Barrel PWA)
1. Pembukaan & Identitas ~45 detik
📷 AKSI LAYAR: Tampilkan wajah di webcam atau buka halaman web Bore & Barrel di laptop.
"Halo semuanya, selamat malam kepada asisten praktikum Pengembangan Perangkat Bergerak tahun 2026.

Perkenalkan nama saya [Nama Lengkap Kamu], NIM [NIM Kamu], dari Shift [Shift Kamu], Kelompok [Kelompok Kamu].

Pada kesempatan kali ini, saya membuat video ini sebagai tugas pengganti praktikum Modul 5 mengenai React Progressive Web App (PWA) II.

Di video ini saya akan mendemonstrasikan langkah percobaan, integrasi database Supabase pribadi, fitur paginasi, lazy load, query caching, dan fitur sharelink. Mari kita mulai."
2. Database Supabase Pribadi ~1.5 menit
📷 AKSI LAYAR: Buka browser ke dashboard Supabase milikmu (tunjukkan tabel products, reviews, favorites), lalu buka file .env dan src/config/api.js di VS Code.
"Sesuai ketentuan poin ke-5, saya tidak menggunakan shared API modul, melainkan sudah membuat dan mengintegrasikan database Supabase pribadi saya sendiri.

Bisa dilihat di dashboard Supabase saya, terdapat tiga tabel utama yaitu products untuk inventaris katalog, reviews untuk ulasan, dan favorites untuk bookmark barang.

Kemudian pada source code di file .env, URL dan Anon Key sudah diarahkan ke project Supabase milik saya sendiri.

Komunikasi datanya ditangani oleh Axios di src/config/api.js, lengkap dengan interceptor yang otomatis menyematkan apikey dan token otorisasi pada setiap request."
3. Langkah Percobaan & PWA ~1.5 menit
📷 AKSI LAYAR: Buka web di browser. Tekan F12 -> tab Application -> klik "Service Workers" dan "Manifest". Tunjukkan banner install PWA di kanan bawah.
"Selanjutnya untuk langkah percobaan sesuai instruksi modul, aplikasi ini dikembangkan dengan ReactJS dan build tool Vite.

Untuk kapabilitas PWA, proyek menggunakan vite-plugin-pwa.

Jika kita inspect di tab Application, bisa kita lihat Service Worker sudah aktif dan terdaftar dengan baik. Pada tab Manifest, metadata seperti nama 'Bore & Barrel', warna tema, dan icon aplikasi 192 serta 512 piksel sudah terpasang.

Di pojok bawah juga tersedia badge instalasi PWA untuk memasang aplikasi ke home screen perangkat desktop maupun smartphone secara luring."
4. Demonstrasi Paginasi ~1.5 menit
📷 AKSI LAYAR: Di halaman katalog, scroll ke bawah ke tombol navigasi angka [1] [2] dan [Next]. Klik halaman 2, lalu klik halaman 1. Buka file src/pages/Catalog.jsx di VS Code.
"Untuk ketentuan poin ke-4 yaitu Paginasi.

Pada katalog ini, saya membatasi tampilan menjadi 6 produk per halaman agar rendering antarmuka tetap ringan dan cepat.

Bisa kita lihat di bawah katalog terdapat tombol paginasi: Previous, nomor halaman, dan Next. Saat saya klik halaman kedua, daftar produk langsung berganti dengan cepat tanpa reload seluruh halaman.

Pada kodenya di src/pages/Catalog.jsx, saya menggunakan state currentPage dan itemsPerPage. Data produk yang tampil dihitung secara dinamis menggunakan useMemo dengan teknik slicing array berdasarkan halaman aktif."
5. Pembuktian Lazy Load ~2 menit
📷 AKSI LAYAR: Tekan F12 -> tab Network -> klik filter "Img" -> reload halaman. Tunjukkan request gambar hanya yang terlihat di atas. Scroll ke bawah pelan-pelan, perlihatkan request gambar baru muncul bertahap di Network tab.
"Masuk ke poin ke-2, yaitu pembuktian Lazy Load pada gambar katalog.

Tujuannya adalah menunda pemuatan gambar sampai elemen tersebut benar-benar muncul di layar saat pengguna melakukan scroll.

Mari kita amati di tab Network dengan filter Img:
Saat halaman baru dimuat, browser hanya meminta gambar untuk produk yang berada di area atas.

Ketika saya mulai scroll ke bawah secara bertahap... perhatikan di tab Network, request gambar baru dieksekusi satu per satu sesuai posisi kartu di layar.

Implementasinya ada di komponen src/components/common/LazyImage.jsx yang menggunakan IntersectionObserver untuk memantau kemunculan elemen di viewport sebelum tag gambar dimuat."
6. Pembuktian Query Caching ~1.5 menit
📷 AKSI LAYAR: Di tab Network (pastikan "Disable cache" tidak dicentang), reload halaman. Sorot kolom "Size" yang tertulis "(disk cache)" atau "(ServiceWorker)". Tunjukkan file src/utils/queryCache.js dan vite.config.js.
"Masih di poin ke-2, selanjutnya adalah Query Caching.

Caching bertujuan menyimpan hasil permintaan data dan aset agar akses berikutnya tidak membebani server dan responsnya seketika.

Buktinya bisa kita lihat di tab Network:
Setelah gambar pernah dimuat, ketika halaman saya reload ulang, ukuran pada kolom Size menampilkan status (disk cache) atau from ServiceWorker. Ini artinya gambar langsung disajikan dari memori lokal komputer tanpa download ulang dari server.

Di sisi kode, hal ini diatur oleh runtime caching Workbox di vite.config.js dengan strategi CacheFirst, serta modul src/utils/queryCache.js yang meng-cache respon JSON dari API selama 5 menit."
7. Penjelasan Kode Sharelink ~1.5 menit
📷 AKSI LAYAR: Klik tombol Share (ikon share) pada salah satu produk -> muncul notifikasi "Link Copied!". Buka tab browser baru, paste linknya (misal: ?gun=1) -> tekan Enter -> tunjukkan halaman detail produk itu langsung otomatis terbuka. Buka kodenya di src/App.jsx.
"Ketentuan poin ke-3 adalah Sharelink Button untuk setiap katalog.

Di setiap kartu produk pada GunCard.jsx dan halaman detail, terdapat tombol Share. Saat diklik, sistem membuat link spesifik berformat parameter ?gun=ID_PRODUK dan menyalinnya ke clipboard.

Fitur ini sudah mendukung deep-linking. Sebagai contoh, ketika link ini saya buka di tab baru, aplikasi langsung otomatis mendeteksi parameter tersebut dan menampilkan halaman detail barang yang bersangkutan.

Kodenya ada di src/App.jsx pada hook useEffect, di mana sistem membaca URLSearchParams saat inisialisasi aplikasi. Jika ada parameter 'gun', sistem langsung mengambil datanya dan mengarahkan tampilan ke mode detail."
